Este é um sistema chamado Planner Organizer, desenvolvido em Python, utilizando Streamlit como interface e lógica de negócio, SQLAlchemy como ORM e PostgreSQL como banco de dados.

O sistema já possui módulos de:

Propostas (com status: Em elaboração → Aguardando aprovação → Aprovada → Em execução → Finalizada)

Vendas

Financeiro

Dashboard (com alertas)

Quando uma proposta é marcada como Finalizada, o sistema já gera automaticamente:

registros de vendas

lançamentos financeiros

comissões

pagamentos de assistentes

❗ NÃO alterar nenhuma lógica existente desses módulos.

🔹 OBJETIVO DA ALTERAÇÃO

Criar um NOVO MÓDULO INDEPENDENTE chamado “Pós-Organização”, sem alterar propostas, vendas ou financeiro.

Esse módulo deve gerenciar ações pós-serviço, com datas e status, e alimentar o Dashboard apenas como lembrete.

🔹 MODELAGEM DO BANCO (CRIAR NOVAS TABELAS)

Criar duas novas tabelas usando SQLAlchemy:

post_organizations

id (PK)

proposta_id (FK → propostas)

cliente_id (FK → clientes)

data_final_projeto (date)

status (ATIVO / CONCLUIDO)

created_at

post_organization_actions

id (PK)

post_organization_id (FK → post_organizations)

action_type (string)

due_date (date)

status (PENDENTE / FEITO / CANCELADO)

notes (texto)

completed_at (datetime)

🔹 GATILHO AUTOMÁTICO

Quando uma proposta mudar para status = FINALIZADA, o sistema deve:

Criar um registro em post_organizations

Criar automaticamente as seguintes ações em post_organization_actions:

Ação	Prazo
AGRADECIMENTO	data_fim + 1 dia
MANUTENCAO	data_fim + 2 dias
FOLLOW_UP	data_fim + 7 dias
FEEDBACK	data_fim + 7 dias
OPORTUNIDADE	data_fim + 10 dias

Todas devem nascer com status PENDENTE.

🔹 INTERFACE (STREAMLIT)

Criar um novo item no menu lateral:
Pós-Organização

Tela 1 — Lista

Exibir:

Cliente

Proposta

Status

Próxima ação pendente

Data da próxima ação

Permitir clicar para abrir o detalhe.

Tela 2 — Detalhe

Exibir todas as ações da pós-organização com:

checkbox para marcar FEITO

data prevista

campo curto de observação

🔹 REGRA ESPECIAL (RETORNO TÉCNICO)

Quando a ação FOLLOW_UP for marcada como FEITO:

perguntar se há necessidade de ajuste

se SIM, criar nova ação:

action_type = RETORNO_TECNICO

due_date definida pelo usuário (entre 15 e 30 dias)

❗ Retorno técnico não é criado automaticamente.

🔹 DASHBOARD

O Dashboard deve exibir alerta se existir alguma ação:

status = PENDENTE

due_date ≤ hoje

action_type ∈ (FOLLOW_UP, RETORNO_TECNICO)

❗ O Dashboard não executa ações, apenas alerta.

🔹 CONCLUSÃO AUTOMÁTICA

Quando todas as ações:

AGRADECIMENTO

FOLLOW_UP

FEEDBACK

estiverem com status FEITO, marcar:
post_organizations.status = CONCLUIDO
